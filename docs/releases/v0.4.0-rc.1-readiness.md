confinement error, #4254 deleted quickstart command, #4247 quadratic status reads)
are closed on current main. Their packages pass the full race/coverage suite;
the extracted quickstart and demo also passed local artifact smoke.

claim release (#4264), Insights query fan-out (#4256), atomic YAML writes (#4245),

Three additional RC follow-ups were audited and improved:

- #4180 already had partition-filtered depth and a telemetry/Insights consumer.
  The new diagnostic reports genuinely unpartitioned approved work only when the
  operator supplies the complete partition-label vocabulary; it also surfaces
  measured starvation in stage output. It never assigns labels or claims work.
  See [backlog health](../guides/backlog-health.md).
- #4179 already had bounded module-cache warmup and activity sampling. Private
  proxy DNS and HTTP 401 failures now retain their scrubbed cause, receive
  operator guidance, and route as infrastructure failures. Filename diagnostics
  and ordinary application failures remain outside that classification.
- #4210 now rejects the reproduced five-second startup crash using six seconds
  of continuous Windows SCM liveness, preserves service-specific exit codes,
  and rolls back failed installation with the daemon log location. Slow-query,
  delayed-crash, cancellation, and rollback tests pass. This is process liveness;
  authenticated application readiness and a native SCM lifecycle remain unproved,
  so the issue should remain open for that evidence.

Official published images (#3275) remain a hard promotion gate. This readiness
pass does not equate an issue's open/closed label with verified behavior.
#4216 is fixed here. #4290's previously delivered checks needed further behavioral
corrections, now tracked in item 14.

The reference deployment also needs functional configuration delivery. Its base
API Deployment is disabled, and the base worker lacks the authenticated API/blob
endpoints needed for stage dispatch. Startup now refuses that incomplete setup
before runtime initialization. The new [opt-in topology preparer](../../deploy/reference/authenticated/README.md)
provides separate daemon/dispatcher state, shared blobs, TLS, and immutable
configuration rollout for one Linux gaggle. Its initializer passed in the actual
minimal image, including executable asset preservation. An adopted local Linux
ARM64 deployment subsequently completed authenticated stage execution and
between-run worker/daemon restart checks; distributed and in-flight recovery
remain unproved. Details and limits follow below.

DSL 3.0 is currently preview; DSL 2.0 remains the supported compatibility
contract. The support matrix now records `effectiveIn: v0.4.0` for DSL 1.4's
already-shipped early removal, while preserving the prior v0.5.0 policy promise.
The exception is narrowly validated and cannot be applied to arbitrary versions.
Both v0.4.0 and v0.4.0-rc.1 pass release-line support validation.
