## Existing blocker audit

The four original must-fix issues (#4266 self-update downgrade, #4267 Linux demo
confinement error, #4254 deleted quickstart command, #4247 quadratic status reads)
are closed on current main. Their relevant regression and release paths still
need verification on the final candidate.

Other open milestone findings include #4210 Windows service readiness, #4180
partition-aware backlog health, #4179 module-download diagnostics, and #3275
published container images. They remain follow-ups to assess before promotion;
this readiness pass does not equate their open/closed labels with verified behavior.
#4216 is fixed here. #4290's previously delivered checks needed further behavioral
corrections, now tracked in item 14.

DSL 3.0 is currently preview; DSL 2.0 remains the supported compatibility
contract. The support matrix now records `effectiveIn: v0.4.0` for DSL 1.4's
already-shipped early removal, while preserving the prior v0.5.0 policy promise.
The exception is narrowly validated and cannot be applied to arbitrary versions.
Both v0.4.0 and v0.4.0-rc.1 pass release-line support validation.

## Evidence and promotion

Local evidence so far (development snapshot; archives are unsigned):

- Combined `go test -race` passed for oidcauth, httpapi, workerhost, dispatcher,
  dslmigrate, workflow, api/validate, and supportmatrix.
- Release/toolkit schema and installer integration tests passed.
- `make deploy-validate` passed before the additional doctor changes.
- `make vulncheck` found no reachable or imported-package vulnerabilities;
  it reported three advisories elsewhere in required modules.
- Portal install/typecheck/build passed; its dependency audit passed in `make ci`.
- Full RC packaging succeeded for all five targets against the actual v0.3.3
  feature and support snapshots. All eleven SHA256SUMS entries verified.
- Extracted macOS ARM64 RC binary passed quickstart init/validate and completed
  the four-stage demo. The Linux AMD64 archive did the same under Docker
  emulation, as UID 65532 with a read-only root, writable scratch, and no network.
  This is container-runtime evidence, not native Linux or Kubernetes evidence.
- Four migrated-workflow runtime scenarios pass: success, retry, reviewer
  repass, and retry plus repass. Real git commits, subprocess consumers, and
  journals prove the consumer sees the latest producer state. Learning artifacts
  intentionally carry new workflow/effective-version identities; tests verify
  those exact content substitutions and preserve all other bytes/events.
- Final doctor checks passed: race tests, CLI/completion tests, manifest render
  and schema validation, module tidy, and the unchanged complexity gate.
- Broad `make ci` is running. Its initial complexity failure was resolved by
  decomposition; the complexity baseline and thresholds were not relaxed.

Evidence artifacts/logs are under `/tmp/goobers-rc1-evidence-20260907` and
`/tmp/goobers-rc-*.log` on the development host; copy final evidence to retained
CI artifacts before promotion. The initial local package identifies the source
as `5595b2db9-dirty`; rebuild after final changes for a release identity.

The distributed exit is defined in [the Goobernetes smoke design](../design/goobernetes-smoke.md):
S1–S9 in one procedure, including Windows/Linux handoff, fresh pods, declared repo
edges, kill recovery, authenticated operations, live visibility, and a negative
network-policy control. Missing observers or unexercised paths are **invalid**, not
passes. Production cluster mutation and kill injection require an explicitly
selected test target before execution.

Promotion remains blocked on retained, complete S1–S9 evidence; official image
publication including the Windows image (#3275); hosted signing/native smoke;
and final integrated CI. The approved decision record identifies image publication
as a hard gate, so customer-built containers alone do not satisfy it. The current
OTLP doctor hook is neither CLI-wired nor an ingestion proof; use recorded collector
observations for telemetry acceptance.

No release tag or publication has been made by this work.
