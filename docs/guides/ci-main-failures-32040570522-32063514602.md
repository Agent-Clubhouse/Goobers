## Run 32040570522 (b437b4d4, "Use indexed active-run sampling (#3206)")

Failing jobs: [`unit`](https://github.com/Agent-Clubhouse/Goobers/actions/runs/32040570522/job/95419066489)
and [`lint (linux)`](https://github.com/Agent-Clubhouse/Goobers/actions/runs/32040570522/job/95419066670).
Both failed in step 1, `Set up job`, after about 45 and 75 seconds, before any
repository code ran. Their check-run annotations:

```
Failed to download archive 'https://codeload.github.com/actions/setup-go/tar.gz/b7ad1dad31e06c5925ef5d2fc7ad053ef454303e' after 3 attempts.
Response status code does not indicate success: 503 (Service Unavailable).   (unit)
Response status code does not indicate success: 502 (Bad Gateway).          (lint (linux))
Back off 11.463 seconds before retry.   /   Back off 18.838 seconds before retry.
```

Root cause: a transient GitHub-side outage of the `codeload.github.com`
action-archive download used to resolve the pinned `actions/setup-go` action.
The 502/503 responses exhausted the runner's three built-in download attempts.
Every other job on this SHA, including the macOS-hosted `unit behavioral suite
(macos)` and `shipped workflow contracts (macos-latest)`, succeeded, and the
downstream `make ci` and `escalate failed main validation` jobs were skipped.
Same-SHA `Flake watch` runs
[32041353434](https://github.com/Agent-Clubhouse/Goobers/actions/runs/32041353434)
and [32044109950](https://github.com/Agent-Clubhouse/Goobers/actions/runs/32044109950)
passed, consistent with a transient infrastructure failure rather than a flaky
test. Confidence: high.

### Ranked hypotheses

Observed facts constrain these: the setup, download and checkout steps passed,
the test step ran to completion (about 9 minutes, not a hang to a job timeout),
and the failure did not reproduce on linux race shards or in the same-SHA
re-run.

1. **Timing-sensitive test failing under macOS runner load (most likely).**
   The macOS suite ran without `-race` and is near its time budget (551s
   against a 300s budget; the budget warning is non-fatal on its own).
   A test with a short deadline, `Eventually` window or sleep-based ordering
   would fail intermittently on a slow shared runner.
   *Confirm by:* the `--- FAIL:` line and its assertion in the raw job log; the
   failing test's duration against its deadline; and a loop reproduction,
   `go test -count=50 -run '<TestName>' ./<pkg>/` on a macOS host, optionally
   with `-cpu 1` or a CPU-limited load generator running alongside.
2. **macOS-specific filesystem or process behaviour** (tmp path symlink
   `/var` to `/private/var`, case-insensitive paths, a file-watcher or socket
   path-length limit, a port or tmp-dir collision with a parallel package).
   *Confirm by:* a path or `bind: ... in use` / `socket path too long` error
   in the log, and by whether the same test fails on repeated macOS runs of
   `.github/workflows/macos-nightly.yml`.
3. **Runner-level fault** (runner OOM, disk pressure, a killed test binary).
   *Confirm by:* a `signal: killed` or `exit status 137`-style line, or a
   missing `FAIL` line with only `exit code 1`, plus the runner diagnostics
   in the log's final lines.

Hypothesis 1 is ranked first because one `go test` failure line normally
accompanies exit code 1, the job otherwise behaved normally, and the suite
duration is within the same band as passing runs.

## Proposed fix approach

1. **Run 32040570522 (infrastructure):** no test or code fix. Do not add
   retries (the repository rule is zero anonymous retries, see
   [Flake management](flake-management.md)). Record it as a closed
   infrastructure incident. If the outage recurs, the optional hardening is to
   reduce dependency on `codeload.github.com` at job start, for example by
   vendoring the setup action, which is a separate decision and not required.
2. **Run 32063514602 (macOS test):** the fix child should first obtain the raw
   log of job 95490093794 from a maintainer with repository admin access (logs
   are retained 90 days by default, so by about 2026-11-15) and read the
   `--- FAIL:` line. If the log has expired, the fix child should run
   `.github/workflows/macos-nightly.yml` and the loop command from hypothesis 1
   against the macOS-only behavioural packages to reproduce. Then:
   - for a timing cause, replace the sleep or fixed deadline with a
     condition-based wait and a generous bounded timeout, and add the test to
     `test/stress/packages.txt` if it is not already enrolled;
   - for a path or port cause, use `t.TempDir()` with `filepath.EvalSymlinks`
     and ephemeral `:0` listeners;
   - file the result as a tracked flake per `flake-management.md`, not as a
     retry or a skip.
3. Do not raise the 300s timing budget in this fix. It is a separate,
   already-reported signal, since the macOS job exceeds it on passing runs too.
