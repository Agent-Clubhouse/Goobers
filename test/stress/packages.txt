# Curated timing/goroutine-sensitive packages. Keep this list small: every
# entry runs under the race detector twenty times in the nightly stress tier,
# unless it has a reviewed `count=N` override.
#
# Settings are `key=value`, in any order:
#
#   count=N   repetitions per shard (1..20, default 20)
#   shards=N  split the package's top-level tests into N balanced `-run`
#             subsets, each repeated `count` times and scheduled as its own
#             nightly job (default 1). The split enumerates every test and
#             assigns the longest measured tests to the lightest shard.
#             test/stress/weights.json records measurements and provenance;
#             new tests use its documented two-second fallback weight.
#   pass=D    REQUIRED. The reviewed wall-clock cost of one race-instrumented
#             pass over the whole package, measured on a hosted runner.
#   exclude=NAME[,NAME...]
#             Exact top-level test name(s) never scheduled into any shard's
#             `-run` set, so they are never repeated under the race
#             detector at all (they still run once, normally, in ordinary
#             CI). Use it for a deterministic, non-concurrent test — a
#             static/type-aware scan, a golden-file compare, anything with
#             no goroutines to race — that a repeat count cannot make more
#             informative but that a slow single pass can make a shard time
#             out. Excluding happens before weighted partitioning, so only
#             enrolled tests contribute to the measured shard weights.
#
# `pass` is what keeps the enrollment honest: `test/stress` refuses a list
# whose implied per-shard budget — count x pass / shards, plus the build
# reserve every invocation pays — exceeds the 30m per-shard `go test` timeout.
# Seventeen consecutive nightly failures came from an entry that quietly did
# not fit that budget (#4222), so an entry that cannot fit must raise `shards`
# rather than be discovered as a timeout.

# Embedded scheduler and claim ledger; site of the timing incident tracked by #21.
./internal/localscheduler pass=45s

# Packages with default-branch failures tracked by the flake ledger.
#
# cmd/goobers is the largest and most concurrency-heavy package in the repo and
# the dominant source of flake reports, so it must not sit at the token count=2
# it was reduced to when its full twenty-repetition race suite stopped fitting
# the per-package budget. pass=23m retains the earlier reviewed whole-package
# hosted wall-time measurement (990-1370s); dividing it by the shard count is
# only the enrollment estimate, not evidence of current per-shard headroom.
# Count-balanced shards exceeded 30m in October, so weights.json now supplies
# measured individual test costs for deterministic duration-based placement.
# Summed per-test elapsed times may overestimate wall time when tests overlap;
# they do not replace a whole-package wall measurement. Hosted stress on the
# final layout remains the check that each shard fits the unchanged timeout.
# All tests retain the full repetition count. TestIntentionalJournal-
# AppendDiscardsUseObservableHelper is a type-aware static scan of every
# tracked production Go file with no concurrency to exercise (added by
# #5018); repeating it up to 20x under -race panicked one shard with
# "test timed out after 30m0s" every night since 2026-09-13 (#5158), so it is
# excluded from stress here and continues to run once, normally, in CI.
./cmd/goobers pass=23m shards=32 exclude=TestIntentionalJournalAppendDiscardsUseObservableHelper
