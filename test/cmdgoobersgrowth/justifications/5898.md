# #5898: say when a watched definition edit only reaches subsequent runs

Growth: about +89 non-test lines and +0 files in `cmd/goobers`.

- `digestdrift.go` gains `pinnedDefinitions`, `supersededWorkflows` and
  the `Superseded` set on the existing drift report, plus
  `workflowDigestDriftNotice` and `reportWorkflowDigestDrift`. When an
  applied reload changes the workflow, goober content or gaggle
  `runControls` that an in-flight run pinned at launch, the daemon now logs
  `config reload: definition change detected; will apply to subsequent runs only`
  with the affected run IDs, next to the existing instance-log annotation.
  Without it, a mid-run edit to `maxRepasses` or a stage timeout looked
  applied while the run kept its launch-time values.
- `configreload.go` captures the before/after definitions around the swap
  and calls the new helper instead of the journal-only one (two lines).

## Could any of it live elsewhere?

The drift report (`inspectWorkflowDigestDrift`, `journalWorkflowDigestDrift`)
and the reload loop that emits it already live in this package, and the
before/after comparison reads the daemon's own scheduler setup
(`Machines`, `GooberDigests`, `Definitions`). Moving it out would mean
moving the whole drift report, which is part of the broader `cmd/goobers`
extraction work rather than this fix.
