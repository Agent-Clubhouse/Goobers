# #4418: Resume re-claims from retained implementation checkpoints

The `recovery-resume` stage command gains a typed result file
(`recovery-resume.json`) and an outcome classifier: no retained work, or
retained work whose base diverged or whose patch no longer applies to current
main, is the ordinary fresh-start path, while every other error stays
fail-closed. The command also reports which prior run it resumed from so the
run journal, status, and read model can show provenance.

The logic belongs in the command package because it is stage orchestration
over existing recovery, claims, and provider-input seams; the reusable
restore and selection mechanics stay in `internal/recovery`.
