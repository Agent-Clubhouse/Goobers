# #7750: Report whole-instance cloud cutover readiness

Growth: +68 non-test lines and +0 production files in `cmd/goobers`.

The reusable assessment, grouping, remediation metadata, and text renderer live
in `internal/cloudreadiness`. Command-package growth is limited to the CLI
boundary: parsing `--format`, buffering machine-readable output until ordinary
configuration validation succeeds, encoding the versioned JSON contract, and
projecting readiness blockers into the existing diagnostics and GitHub
annotation surfaces.

Keeping that adapter in `cmd/goobers` preserves the single authoritative
validate/lint engine and its existing source-file attribution. Moving it into
the shared library would couple reusable cutover assessment to CLI writers,
diagnostic collectors, and config-tree path rendering.
