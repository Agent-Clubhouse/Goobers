# #6919: ADO open-PR eligibility backstop in backlog-query

`backlog-query` excluded items referenced by an open goober pull request only
when the code was on GitHub, so an Azure DevOps gaggle re-selected items whose
pull request was still open and opened duplicate pull requests.

The growth is the ADO counterpart of `openPRIssueNumbers`, which already lives
in `cmd/goobers/backlogquery.go`: a narrow reader interface, the stage wiring
that builds the ADO pull-request provider from the stage's `github:pr:write`
credential, and the topology-aware mapping from pull-request references to
backlog items (it reuses `referencedIssueNumbers` and `closingIssueURLs`,
both in `cmd/goobers`). The new provider read (full description plus native
work-item links) lives in `providers/ado_prreferences.go`. Moving the mapping
out of `cmd/goobers` would mean moving the PR-body reference grammar shared
with `post-merge`, which is a broader extraction than this fix.
