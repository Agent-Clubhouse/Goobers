# Terminate engine runs whose cancellation is never honoured (#5407)

When no worker can poll, the stall sweep's CancelWorkflow is never processed,
so a run stuck at run.started holds its claim and concurrency slot forever.
The growth is the sweep's escalation path in `cmd/goobers/stalledengineruns.go`
(when to escalate, the terminate-close-release ordering and the instance-log
annotations), a bounded `terminateUnresponsive` on the existing
`engineRunGuards`, and the `CloseEngineRun` wiring that hands the sweep the
daemon's live journal writer.

It stays in `cmd/goobers` because it is daemon policy over pieces that already
live there: the stall sweep, the engine guards (which own the Temporal client
and the run-id resolver) and the scheduler slot release. The reusable part, the
terminal journal batch, lives in `internal/engine` (`TerminatedRunClosure`)
beside the reservation batch it closes.
