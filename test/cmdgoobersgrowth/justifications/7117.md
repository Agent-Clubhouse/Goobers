# #7117: Backprop shadow mode gaggle override and comparison report

Growth: about +150 non-test lines and +1 file in `cmd/goobers`
(`backprop_shadow.go`).

## Why the growth belongs in the command package

- **`goobers telemetry shadow`** is a new read-only CLI subcommand: flag
  parsing, help text, opening the instance read model and config directory,
  and rendering the report as text or JSON. Subcommand handlers are registered
  in `runtime_capabilities.go` and must live in this package.
- **`withStatusBackpropOverrides`** wraps the existing status fleet-summary
  loader so `goobers status` resolves each workflow's Backprop mode against
  its gaggle's override. It lives in its own file to keep churn out of
  `status.go`.
- Small registration edits in `completionmodel.go`, `clisynopsis.go` and
  `telemetry.go` list the new subcommand.

## Could any of it live elsewhere?

The analysis itself (`readservice.StoredShadowBackprop`,
`readservice.GaggleBackpropOverrides`, `creditgraph.ObserveShadowRun` and
`apiv1.ResolveBackpropMode`) already lives outside `cmd/goobers`. What
remains here is CLI and status presentation glue with no other consumer.
