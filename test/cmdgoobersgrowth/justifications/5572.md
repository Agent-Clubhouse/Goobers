# Honor the executor's effective stage deadline in provider commands

Issue #5572: provider subcommands budgeted their context (and therefore their
rate-limit waits) from `inputs.timeout` alone, so a stage whose deadline came
from `timeoutSeconds` or the runner default was budgeted as if it had the
built-in 10m. `stageTimeout` in `cmd/goobers/providercmd.go` now reads the
effective deadline the executor injects first. The growth is a few lines in the
existing helper every provider command already shares; the deadline itself is
resolved and injected by `internal/executor`.
