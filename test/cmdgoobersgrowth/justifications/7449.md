# #7449: bound intervention claim waits by request admission

Growth: context-aware variants of the existing claims-lock helpers and typed
intervention error mapping in `cmd/goobers`.

- Intervention claim reacquisition now receives the API admission context.
- The lock wait observes cancellation and is capped below the request deadline,
  so configured waits longer than the route budget cannot escape that budget.
- A claims-lock timeout is preserved as the actionable retryable
  `claims_lock_timeout` response instead of being flattened into a generic
  claim-reacquisition failure.
- Engine-backed interventions use a route-specific client timeout that
  contains the server's durable HITL delivery budget; unrelated mutations keep
  the existing shorter transport timeout.

## Could any of it live elsewhere?

The generic intervention service carries the context through its `ClaimStore`
interface. The deadline calculation, file-lock acquisition and holder-aware
timeout type already belong to the command package because that is where the
instance configuration, claim-lock journal events and file-backed claim store
are wired together.
