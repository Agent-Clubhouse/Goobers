# #6876: hosted-progress publisher retries transient errors

The run-wait reporter in `cmd/goobers/runprogress.go` grows by a few non-test lines: it now warns once and keeps publishing on a transient hosted-progress failure, stopping only on `hostedprogress.IsPermanent`. The two wait call sites in `run.go` call `Finalize` unconditionally so a terminal publish lost to a transient failure is still completed with the run's real conclusion. The retry, backoff and terminal-labelling logic lives in `internal/hostedprogress`; only the reporter that owns the CLI warning output and the wait call sites stay in the command package.
