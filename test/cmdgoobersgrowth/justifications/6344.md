# #6344: Retire own orphaned provider claim epochs

backlog-query gains a small, command-local reconciliation guard for provider
claim epochs that outlive local ledger history. The code must stay at the claim
confirmation boundary because it has to combine the active backlog claim session,
the provider's current open epoch, the stage instance identity, and the instance
run-directory layout before authorizing a ledger-backed release.

The reusable pieces stay outside cmd/goobers: claim history retention remains in
internal/localscheduler, run terminality remains in internal/journal and
internal/instance, and provider epoch parsing remains in providers. No command,
flag, or new package is added.
