# #5414: fail a pod implementation review closed when it has no run diff

Growth: about +30 non-test lines and +0 files in `cmd/goobers`.

- `agentickitwriter.go` (+1): `WriteKit` stamps the new
  `agentickit.Kit.ReviewRequiresDiff` flag from the dispatch attempt. The kit
  is verified and content-addressed, so the flag reaches the pod the same way
  as the review mode does, and is never a listable env var.
- `dispatchagentic.go` (+8): when the reviewer diff the pod computes is empty
  and the kit requires one, no reviewer session starts. The pod either
  surrenders the mechanical empty-diff verdict or fails with
  `reviewer_diff_missing`.
- `dispatchreview.go` (+20, mostly the doc comment): `missingReviewerDiff`
  decides between those two outcomes. A writable reviewer saw an empty
  `base...HEAD`, so it gets the same mechanical empty-diff verdict the engine
  and local runner use, which routes like any other failed review. A
  repo-readonly or scratch reviewer cannot see the run branch, so the pod
  fails closed and names `workspace: repo` as the remedy.

## Could any of it live elsewhere?

No. The pod's review path, its checkout and its diff computation all live in
this package. The classification of which gates need a diff lives in
`internal/runner` (`ReviewsImplementation`) and is shared with the engine.
