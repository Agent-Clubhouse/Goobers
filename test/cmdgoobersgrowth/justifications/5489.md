# #5489: bounded authoritative claimability for fleet backlog health

Growth: about +285 non-test lines and +1 file in `cmd/goobers`.

- `fleethealth_claimability.go` (new). It derives each counter's admission
  identity from its workflow (gaggle namespace, polled provider, pinned claim
  visibility, longest `backlog-query` lease), caches one classification per
  poll, and wires the daemon's read-only sources: the claim ledger file, the
  learned blocked records, and a quota-metered, retry-free shared lease store.
  Those sources are reachable only through helpers that live in this package
  (`claimLedgerFileName`, `heldStateStore`, `decodeBlockedRecords`,
  `blockedRecordAppliesToRepository`, `daemonSharedClaimProvider`,
  `scrubbedSharedClaimStore`, `providerQuotaAccounting`, `schedulerSetup`).
- `fleethealth_backlog.go` splits the sampler loop into a per-source fold and
  adds the claimable/held reasons to the condition writer, keeping each
  function under the complexity caps.
- `runnerwiring_counters.go` (+4) retains a bounded candidate prefix from the
  existing poll and attaches the admission identity in both counter builders.

## Could any of it live elsewhere?

The classification policy itself is outside this package, in the new
`internal/claimability` (no `cmd/goobers` dependency), with
`sharedclaim.Inspect` exposing the read-only half of `Acquire`. What remains
here is daemon wiring over stage/daemon plumbing that only exists in
`cmd/goobers`. Moving the blocked-record and ledger path helpers into a shared
package would let this wiring shrink, but that is part of the broader
`cmd/goobers` extraction work, not this change.
