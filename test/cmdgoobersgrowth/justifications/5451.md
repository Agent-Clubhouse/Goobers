# Fix #5451: drop provider claim markers that outlive their ledger lease

Growth comes from the backlog claim session in `cmd/goobers`:

- **`confirmProviderClaim` and `leaseStillHeld`** (`claimobservation.go`).
  After the provider claim marker is written, the session re-reads its own
  lease. If the lease was released or replaced while the provider call was
  in flight, it retracts its marker and returns `ledgerLeaseLostError`. The
  check is backlog-query stage policy (which lease the stage claimed, which
  marker it wrote), so it belongs with the rest of that stage's claim flow.
- **`dropLostLease`** (`backlogquery.go`). This removes the item from the
  session's claimed and newly-claimed sets and records a ledger refusal. It
  only changes the session's in-memory bookkeeping, which lives in this
  package.
- **`claimEntryWire`** (`writeplanes.go`, +1 line). This forwards the new
  `RenewedAt` field to the claims plane.

The ledger change (renewals keep `ClaimedAt` and record `RenewedAt`) is in
`internal/localscheduler`, not here.
