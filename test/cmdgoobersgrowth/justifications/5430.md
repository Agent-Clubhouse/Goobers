# #5430: failure-streak comment names the label that actually parks the item

Growth: +49 non-test lines and +0 files in `cmd/goobers`.

- `escalationCommenter.GetWorkItem` (`cmd/goobers/runnerwiring_notifications.go`,
  +49 lines). The failure-streak comment now reads the item's current labels so
  it can tell the operator to remove `goobers:merge-escalated` (or
  `goobers:needs-human`) instead of always naming needs-human. The read must
  go through the same per-call routing as the commenter's existing
  `ListComments`/`UpdateWorkItem`/`UpdateComment`: ADO backlog-project
  resolution, Gitea base-URL resolution, the rotation-aware token resolver and
  secret registration, and the `pr/<n>` claim-key mapping. All of that lives
  on `escalationCommenter` in this package. An ADO `pr/<n>` key, whose
  number is not a Boards work-item id, is read through the PR-labels endpoint
  (`PullRequestLabelNames`) on the code repository instead.

The label-selection and comment-text policy is in `internal/gate`
(`WorkItemReader`, `HumanParkLabels`), and the new label constant is in
`internal/lifecycle`. Only the provider routing is here.

## Could any of it live elsewhere?

The four provider-routing methods on `escalationCommenter` could move together
into an internal package once the instance-layout helpers they depend on
(`backlogRepoRefForGaggle`, `newConfiguredADOProvider`,
`newGiteaProviderForStage`) are extracted. That is part of the broader
`cmd/goobers` extraction work, not this fix.
