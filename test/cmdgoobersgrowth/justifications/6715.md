# Wait for projector sweeps before closing read stores (#6715)

`startProjector` launched the retention loop and repair sweeper as bare
goroutines, and its stop function only cancelled them. Setup rollback and daemon
shutdown close the read model and intake stores right after stop returns, so an
in-flight sweep could still hold a SQLite connection; on Windows that open
handle blocks removing the instance directory. The growth (+6 lines, including
a comment) is a `sync.WaitGroup` that stop waits on before stopping the
commit loop. It stays in `cmd/goobers` because that is where these loops are
launched; the projector's own drain schedule is fixed in
`internal/readmodel/projector`.
