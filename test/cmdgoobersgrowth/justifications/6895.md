# #6895: daemon advertises startup budget and progress to waiting workers

Growth: about +54 non-test lines in `cmd/goobers` (`startup_api.go`,
`startupphase.go`, `daemontelemetrystartup.go`, `worker.go`, `up.go`).

The read-model half of #6895 moved its logic into `internal/readmodel` and
shrank `cmd/goobers` slightly; this growth is the worker-readiness half.

## Why the growth belongs in the command package

- `startupphase.go`: `startupPhaseTracker` gains a progress counter, bumped
  where it already records phase changes, budget inputs and recovery
  progress. The tracker, its derived startup budget and its lock live only in
  the daemon command.
- `startup_api.go`: `startupHints` reads the tracker's budget snapshot and
  progress, `daemonStartingHandler` attaches them to the existing
  "daemon is starting" 503, and `trackStartupProgress` counts each scheduler
  setup progress report (read-model build and re-projection counts) on the
  tracker. All three wrap state owned by this package.
- `daemontelemetrystartup.go` / `up.go`: pass the tracker into the existing
  startup progress wiring.
- `worker.go`: the `--blob-probe-wait` help text now says the daemon's hints
  extend the wait.

## Could any of it live elsewhere?

The header protocol (names, encoding, validation, caps) is in
`internal/startuphint`, the response headers reach the worker through
`internal/dispatcher`, and the bound itself (budget plus grace, progress
restarts the stall window, hard cap) is in `internal/workerblob`. Only the
tracker-facing glue remains in `cmd/goobers`.
