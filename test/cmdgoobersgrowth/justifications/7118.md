# Backprop per-stage attribution checkpoints (#7118)

Growth: +39 non-test lines and +0 files in `cmd/goobers`. All analysis lives
in `internal/creditgraph` (`stage.go`, `checkpointer.go`) and the observer
composition lives in `internal/telemetry/ingest` (`RunObserversContext`).

## Why the growth belongs in the command package

- **`goobers trace` read surface** (`cmd/goobers/trace.go`, most of the lines).
  `trace` is the existing per-run read surface for `attribution.json`; it now
  also loads `attribution-stages.json`, verifies it against the journal,
  emits it under `stageAttribution` (or `stageAttributionError`) in JSON
  output, and prints one summary line per stage checkpoint. The Backprop JSON
  fields moved into an embedded `traceBackpropJSON` so `runTraceWithFactories`
  does not grow. A small
  `traceBackprop` value carries both records through the existing summary
  helpers instead of adding parameters.
- **Observer wiring** (`cmd/goobers/daemon.go`, `cmd/goobers/journalplane.go`,
  one call each plus a comment). The two places that already install the
  read-model intake observer now install the composed observer, so stage
  checkpoints are queued for both local-runner and engine-driven runs.

## Could any of it live elsewhere?

The trace rendering could move into a shared trace-view package if the
`cmd/goobers` extraction work creates one; until then it stays next to the
existing attribution summary it extends.
