# Unify root and attribution identity (#7642)

The additional command wiring preserves ownership and correlation for roots
that historically wrote different lifecycle and journal-attribution IDs.
Pinned child admission, provider/shared claims, retained config recovery, and
telemetry lookup now accept a historical ID only when the root-scoped alias
resolver proves that it belongs to the canonical `.instance-id`.

These checks belong at the command package's ownership boundaries: they retain
the original journal, claim token, and provider attribution while preventing a
foreign root from acquiring them. Identity validation, migration, alias
persistence, and lookup remain reusable in `internal/instance`; rollup query
matching remains in `internal/telemetry/rollup`, and no shared growth snapshot
is changed.
