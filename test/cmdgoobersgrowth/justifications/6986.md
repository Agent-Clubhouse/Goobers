# #6986: resolve ready items a capped full transition scan cannot reach

The backlog-health stage failed the whole snapshot when a full ready-label
transition scan (page-capped, and bounded by how much repository event history
the provider serves) did not reach a ready item's only label-add event. The
growth is a small fallback beside the existing ledger code in
`cmd/goobers/backloghealth*.go`: it resolves just the unexplained items from
their own per-item label history (one bounded call each), folds those
transitions into the durable ledger so the next resumed cycle does not rescan,
and records the lookup count in the existing scan provenance. The
transition-replay loop was split out of `annotateReadyTimes` so the fallback
and the annotator share one definition of "active label-add".

## Could any of it live elsewhere?

The fallback is stage policy built on stage plumbing that only exists in this
package: the scheduler-state ledger seam (`openStageStateStore`,
`updateJSONState`), the ledger cursor encoding, and the stage's provider-error
classification. It moves with the rest of `backloghealth*.go` if that stage is
ever extracted.
