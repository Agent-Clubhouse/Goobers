# #6918: acknowledge assessed feedback without masking newer human comments

Growth: +153 non-test lines and +1 file (`feedbackack.go`) in
`cmd/goobers`.

## Why the growth belongs in the command package

- **Shared marker between watcher and publishers.** `pr-comment-watch`
  (`prcommentwatch.go`) reads the hidden feedback-ack frontier, while
  `respond-to-findings` and `resolve-review-threads` write it. All three are
  command implementations in `cmd/goobers`, and the frontier is computed
  from the remediation brief that `readLatestRemediationBrief` (also in
  `cmd/goobers`) already loads. `feedbackack.go` keeps the render/parse pair
  in one small file next to its only callers.
- **Watcher predicate.** `latestUnaddressedHumanComment` now applies the
  per-comment frontier and reports legacy unbound acknowledgements in
  `unboundAcknowledged`; this is the command's own routing rule.
- **ADO verdict comments.** `apply-verdict` posts a fresh, append-only
  verdict thread comment on ADO each pass; it now carries an empty frontier
  (one small helper in `applyverdict.go`) so it cannot mask feedback.
- **Help text.** The documented v1 limitation is replaced by the frontier
  semantics.

## Could any of it live elsewhere?

The marker format could move to a shared package once a non-command caller
exists. Today the brief reader, both publishers and the watcher are all in
`cmd/goobers`, so moving only the marker would add an exported API with no
other consumer.
