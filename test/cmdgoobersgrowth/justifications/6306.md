# #6306: fetch the missing delta base before pure-pod recovery import

Growth: +9 non-test lines and +0 files in `cmd/goobers`, all in`n`cmd/goobers/recoverypublication.go`.

## Why the growth belongs in the command package

`PublishRecovery` is where the API delivery service wires its intake options.
These are the authorization callback, the worktree manager and the repository
URL. The new `EnsureImportBase` closure joins those three pieces, which only
exist in this command-layer service.

Before the import, it revalidates the issue lease with the existing
`authorizeRecoveryDelivery`. It then asks the manager to fetch a delta
bundle's missing base into the managed recovery mirror. All of the mechanism
lives in internal packages:

- the hook contract and `RequiresImportBase` are in `internal/recovery`;
- the mirror fetch is in `internal/worktree`.

## Could any of it live elsewhere?

No. The closure is the binding between command-owned authorization and the
manager instance. Moving it would mean passing the same three values through
another layer, with no behavior gained.
