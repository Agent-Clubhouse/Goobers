# #7071: update a behind PR that is red only because its base was

`update-behind-pr` sent every failing PR to full remediation. A PR whose CI ran
while its base was red then got an agent that had nothing in the PR's diff to
change, and the no-work guards parked it. The stage now updates such a PR
through the API when every check failing on its head also failed on the base,
at the merge-base or at a base commit between it and the live tip.

The growth is `failingChecksInheritedFromBase` with small helpers that read the
base branch's first-parent commits since the merge-base and their failing checks, the
`pullRequestLiveBaseMergeBase` helper split out of `pullRequestBehindLiveBase`
so both share the merge-base read, and a longer help text. All of it is in
`cmd/goobers/updatebehindpr.go`.

## Could any of it live elsewhere?

The check runs over the stage's `remediationProvider` surface and its
per-tick base-tip cache, both of which exist only in this package. The
provider reads it uses (`CIFailures`, `RefCheckStates`, `CompareCommits`,
`BranchTipSHA`) are already in `providers`, and the one new read,
`FirstParentHistory`, is added there too. Moving a name-set comparison of a few
lines into its own package would not shrink this package in any useful way.
