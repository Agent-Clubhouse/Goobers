# #6733: opt-in handoff schemas for pre-DSL-3.1 producer results

Growth: +3 non-test lines and +0 files in `cmd/goobers`.

## Why the growth belongs in the command package

`applyRunnerConfigFinalizers` in `runnerwiring.go` copies the instance's
`decisionGate.handoffSchemas` bindings into `runner.Config`. Translating
instance configuration into runner configuration is composition-root wiring,
and `cmd/goobers` is the only package that holds both the loaded
`instance.Config` and the `runner.Config` it builds.

## Could any of it live elsewhere?

The binding model, validation and the off-by-default gating live in
`internal/decisiongate` (`Settings.ResultSchemas`), and the validation
itself lives in `internal/runner`. Only the one assignment remains here.
