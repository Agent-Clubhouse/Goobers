# #5894: mark runner-synthesized verdicts explicitly

Growth: +21 non-test lines and +0 files in `cmd/goobers`.

- `verdictview.go` (+18 net). The trace and escalation verdict view now
  carries the new `synthesized` marker. It also has a small `MarshalJSON`
  that leaves `findings` out for a synthesized verdict, so trace JSON no
  longer shows a runner-generated verdict as a clean review with an empty list.
  The human render prints one line saying the reviewer did not run.
- `status.go` (+3). `goobers status` prints the same note for the latest
  review when it was synthesized.

## Could any of it live elsewhere?

The marker itself, its schema rule and the producers are in `api/` and
`internal/gate`. The operator summaries are in `internal/readservice` and
`internal/readmodel`. What is left here is how these two CLI views render a
verdict, and that rendering code already lives in this package.
