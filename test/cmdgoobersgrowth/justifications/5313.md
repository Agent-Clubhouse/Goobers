# #5313: implementation reliability line in `goobers status`

Growth: +20 non-test lines and +0 files in `cmd/goobers`.

## Why the growth belongs in the command package

- **One rendered line in `renderStatus`** (`cmd/goobers/status.go`). The
  text status table is the CLI's own presentation of each run, and it already
  renders the review, blockers, and diagnostics lines in the same loop. The
  new line prints `Operator.Reliability` when the read service projected it.
- **A `draft` result output from `open-pr` and child publication**
  (`withOpenPRDraft` in `cmd/goobers/openpr.go`, plus a guarded map entry in
  `childpublication.go`). The PR-opening commands are the only producers that
  receive the provider-reported draft state of the PR they opened or reused;
  journaling it as a stage output is what lets both read paths report the
  retained PR's draft state. When the provider does not report it, no output
  is written and status keeps `unknown` rather than guessing.

## Could any of it live elsewhere?

The projection and its formatting already live in `internal/readservice`
(`reliability.go`, `RunReliability.StatusLine`), shared with the HTTP API
and the dashboard. Only the three-line call site that decides where the line
appears in the text table, and the draft output its producers write, remain
in `cmd/goobers`.
