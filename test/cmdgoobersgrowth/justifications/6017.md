# #6017: retry a harness sign-in probe the provider rate limited

Growth: about +276 non-test lines and +1 file in `cmd/goobers`.

- `preflight.go`: the per-group harness preflight becomes
  `harnessGroupPreflight` (`run`, `finish`, `modelCredential`, `check`, `key`)
  so the same check can be re-run later, and it consults the probe backoff
  keyed by harness, options, command, environment policy and credential
  fingerprint. `harnessPreflightFailures` tracks which refusals are
  wholly transient (`addRefusal`, `transientRefusal`, `recheck`, `reason`).
  The daemon preflight returns that structure instead of a flat map.
- `harnesspreflighttransient.go` (new): the process-wide throttle, the
  refusal text, and the daemon's background re-probe
  (`harnessGroupRecheck`, `harnessWorkflowRecheck`). That re-probe implements
  `localscheduler.HarnessRecheck`, so a workflow refused at startup because
  the provider was rate limiting is admitted again once it recovers.
- `workerwiring.go`: the worker carries the next probe time on a transient
  refusal (`InfrastructureFailureUntil`) so the engine's retry waits for it.
- `daemon.go`, `childdaemon.go`, `up.go`: wiring and the help-text sentence.

## Could any of it live elsewhere?

The reusable parts already moved out. Output classification
(`TransientPreflightError`, `classifyTransientProbeOutput`) and the backoff
schedule (`harness.ProbeBackoff`) live in `internal/harness`. The
recheck/transition journaling contract (`HarnessRecheck`,
`workflow.readmitted`) lives in `internal/localscheduler` and `internal/journal`.
What remains here is the preflight composition itself. It needs
`harnessAdapterFor`, the agent:model credential resolvers and the
workflow-to-harness grouping, which are all `cmd/goobers` composition roots,
and a re-probe has to rebuild exactly that composition. It moves with the
harness preflight in the broader `cmd/goobers` extraction, not in this fix.
