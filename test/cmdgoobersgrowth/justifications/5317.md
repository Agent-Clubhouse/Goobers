# #5317: provider authorization health as a pre-claim readiness predicate

Growth: +42 non-test lines and +1 file in `cmd/goobers`.

- `providerauthhealth.go` (new) is thin daemon wiring. It builds the
  `localscheduler.ProviderAuthHealth` gate from the daemon's instance
  credential resolver and journal scrubber. It maps a workflow that opted
  into `readiness.requireProviderAuthorization` to its effective repository
  (`backlogCounterRepoRef`) and credential ref. It also adapts the GitHub
  provider constructor (`newGitHubProvider`) into the verifier callback.
- `daemon.go` changes two existing lines in `buildSchedulerDefinitions` to
  create the gate set once per reload and attach a gate to each entry.

## Could any of it live elsewhere?

The gate, the cache, the classification and the dispatch refusal are in
`internal/localscheduler`. The read-only probe is in `providers`. What remains
depends on helpers that exist only in this package: the credential resolver
wiring, `backlogCounterRepoRef` and the GitHub provider constructor options.
It would move along with them in the broader `cmd/goobers` extraction work.
