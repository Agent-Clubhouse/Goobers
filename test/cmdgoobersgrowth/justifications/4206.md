# #4206: issue ownership scope governs every issue write

Growth: about +315 non-test lines and +1 file (`cmd/goobers/ownershipscope.go`)
in `cmd/goobers`.

## Why the growth belongs in the command package

- **`ownershipscope.go` (new, ~177 lines).** It reads the stage's
  `ownershipAssignees`/`ownershipUnassigned` provider inputs and wraps the
  stage's repository provider. Every issue write the stage makes (update,
  status change, claim, claim release) then refuses issues owned outside the
  gaggle's scope, returning one typed policy refusal. The wrapper sits where
  the provider stages build their provider (`stageprovider.go`,
  `providercmd.go`). That way the refusal is centralized instead of repeated
  in each stage.
- **`backlogreconcile.go`, `backlogresweep.go` and `backlogquery.go`.** These
  stages filter candidates through the same scope before writing. The earlier
  bug was that they relabeled and commented on issues assigned to someone
  else.
- **`runnerwiring.go`, `workerwiring.go`, `daemon.go` and
  `enginerunspec.go`.** These plumb the gaggle-level `issueOwnershipScope`
  config into the StartSpec and stage inputs, on both the local and worker
  paths. The ownership-input helper keeps `buildRunnerConfig` under its body
  baseline.

## Could any of it live elsewhere?

The scope predicate (`permitsAssignee`) could move into `providers` next to
`WorkItem.AssigneeMatches` once a non-CLI caller needs it. The provider
wrapper depends on the CLI's provider-input plumbing (`providerInput`), so
today it belongs with the other provider-stage glue in `cmd/goobers`. Moving
it would be a follow-up to the broader `cmd/goobers` extraction work.
